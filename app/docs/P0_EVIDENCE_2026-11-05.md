## Изолированный прогон автопилота

Тест `acceptance-simulation` и PostgreSQL-набор подтверждают:

- рабочий план не изменяется;
- тестовый день создаёт показы, переходы, расход и обращения только в копии;
- дорогое направление останавливается;
- остаток переносится в лучшее направление без роста общего лимита;
- пограничный результат создаёт A/B-гипотезу;
- A/B-решение формируется после минимального срока и выборки;
- остановку и перенос можно откатить;
- без свежего сохранённого отчёта Budget Guard запрещает запись;
- бизнес вне пилотного UUID игнорируется;
- внешних запросов на изменение рекламы нет.

Это воспроизводимое доказательство логики, но не доказательство реального
production-трафика.

## Worker

Neon trigger `ritm-autopilot-every-15-min` включён и вызывает функцию
`autopilotcron`. После контрольного запуска в 07:15 UTC production вернул:

```json
{
  "configured": true,
  "writeEnabled": false,
  "pilotBusinessConfigured": false,
  "lastSucceededAt": "2026-11-05T07:15:43.959Z",
  "consecutiveFailures": 0,
  "heartbeatFresh": true,
  "healthy": true
}
```

Это подтверждает внешний запуск по расписанию. На бесплатном Render приложение
может просыпаться с задержкой, поэтому такой режим подходит для пилота с шагом
15 минут, но не для реакции в реальном времени.

## Production-данные

Пилотный бизнес: `abe0f2c5-fe06-4d88-a900-2e0fb32dc237`. В рабочей базе у него
есть успешно созданная поисковая кампания №715814474 и три объявления,
отправленные на модерацию. Последняя отправка подтверждена журналом записи, но
после неё ещё не сохранена контрольная проверка решения Яндекса.

У этого бизнеса пока не выбраны счётчик и цель Метрики. Поэтому сервер теперь
добавляет блокировку `analytics_not_configured` и запрещает `Campaigns.resume`,
даже если Яндекс одобрит объявления. Регрессионный тест подтверждает, что при
таком состоянии внешней записи не происходит.

Worker раз в 15 минут проверяет решение модерации только для точного UUID
пилотного бизнеса. Проверка использует только чтение API, сохраняет один
идемпотентный control-review на временной интервал и не запускает показы.

Свежего отчёта Директа по исполненной кампании нет. Другой отчёт с ненулевыми
показателями не связан с этой кампанией и поэтому не используется автопилотом.

Защитные флаги оставлены выключенными:

```text
AUTOPILOT_ENABLED=false
DIRECT_RESUME_PILOT_ENABLED=false
```

## Что ещё нужно для live-доказательства

1. Задать в Render
   `LIVE_PILOT_BUSINESS_ID=abe0f2c5-fe06-4d88-a900-2e0fb32dc237`.
2. В интерфейсе пилотного бизнеса выбрать счётчик и цель Метрики, затем
   обновить рекламный план.
3. Дождаться сохранённого control-review с решением модерации Яндекса.
4. Зафиксировать лимит, период и ответственного за аварийную остановку.
5. Пополнить кабинет на согласованную минимальную сумму.
6. Временно включить `DIRECT_RESUME_PILOT_ENABLED` и подтвердить запуск в
   интерфейсе.
7. Получить и сверить свежий отчёт Директа именно по исполненной кампании.
8. Сохранить показы, расход и обращение из Direct и Метрики.
9. Только после сверки отчёта включить `AUTOPILOT_ENABLED`.
10. Сохранить read-back остановки, переноса остатка и отката.

До выполнения этих шагов нельзя честно утверждать, что P0 с реальными деньгами
закрыт.
