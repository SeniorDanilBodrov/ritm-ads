# Статус ТЗ

Статус ниже описывает код текущей ветки. «Реализовано» означает, что путь есть в
production-коде и покрыт автоматическими проверками. Реальные показы, расходы и
конверсии отмечены отдельно: их нельзя подтвердить unit-тестом.

| Требование | Статус | Подтверждение и граница |
| --- | --- | --- |
| Google-вход | Реализовано | Authorization code, PKCE, state/nonce, проверка ID token; OAuth-параметры задаются окружением |
| Подключение своего Яндекс-кабинета | Реализовано | Прямой OAuth и Direct API, выбор доступного логина, шифрование токена; второй независимый владелец ещё не прошёл приёмку |
| Описание бизнеса и бюджет | Реализовано | Диалог с Ритой сохраняет профиль, услугу, город, преимущество и лимит |
| Страница без собственного сайта | Реализовано | Пользователь может выбрать созданную страницу для клиента |
| Метрика и обращение | Реализовано | Счётчик, цель и инструкция установки; проверка произвольного внешнего сайта остаётся ручной |
| План рекламы | Реализовано | Поиск, регион, фразы, не менее трёх согласованных объявлений и периодный лимит |
| Создание кампании | Реализовано, live-доказательство ограничено | Создаётся выключенная кампания и связанные объекты, затем выполняется read-back. Существующий пилот подтверждал черновик без показов |
| Изображения Kie.ai | Реализуется в текущей ветке | Генерация, хранение, ручное согласование; загрузка в Direct и `AdImageHash` проходят финальную интеграцию |
| Модерация | Реализовано за флагом | Отдельное действие, журнал до записи, read-back, запрет автоматического повтора при неопределённом ответе |
| Запуск показов | Реализовано за флагом | Проверки модерации, оплаты, периода, лимита и свежего расхода; контролируемый платный запуск ещё не проведён |
| Остановка неэффективной рекламы | Реализовано в PostgreSQL-контуре | Решение по свежим атрибутированным данным, suspend и read-back; live-доказательство на трафике ещё не собрано |
| Перенос остатка | Реализовано в PostgreSQL-контуре | Сумма лимитов сохраняется, донор уменьшается первым; live-доказательство ещё не собрано |
| Откат | Реализовано | Компенсирующие действия журналируются и читаются обратно; потраченные средства не возвращаются |
| A/B объявлений | Реализовано за флагами | Неизменяемый план, вариант Б, отдельный отчёт и решение; реального трафика пока нет |
| A/B аудиторий | Частично | Можно зафиксировать эксперимент и связать две существующие кампании; автоматическое создание второго направления ещё не включено |
| Статистика | Реализовано | Direct Report и Метрика сохраняются раздельно; ненулевое совпадение на live-трафике ещё нужно доказать |
| Budget Guard | Реализовано | Пороговые правила, журнал действий, сохранение общего лимита и fail-closed при несвежих данных |
| История причин | Реализовано | Человеческий текст в ленте, технические поля в деталях |
| Always-on запуск очередей | Подготовлено | Neon Function и защищённый tick-маршрут есть; нужно развернуть trigger и проверить доставки |
| XLSX | На повторной проверке | Экспорт есть; зависимости и формульная безопасность проходят отдельный аудит |
| Мобильный интерфейс | На повторной проверке | Основной адаптив реализован; добавляются браузерные E2E и visual-regression |
| Независимое развёртывание | Инструкция готова | Нужен фактический прогон на второй машине без подсказок автора |

## Что блокирует полную production-приёмку

1. Развернуть Neon Function trigger и проверить, что он будит очереди после
   засыпания Render.
2. Провести запуск с заранее согласованным малым лимитом.
3. Сохранить отчёты с показами, расходом и обращениями.
4. Зафиксировать остановку проигравшего направления, перенос остатка и откат.
5. Либо провести настоящий A/B-тест, либо письменно согласовать
   воспроизводимый тестовый прогон без реального трафика.
6. Повторить установку из чистого клона на другой машине.
