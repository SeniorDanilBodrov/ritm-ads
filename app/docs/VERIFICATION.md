## Исправления, найденные при проверках

1. После исчерпания всех направлений пополнение бюджета оставляло кампании без доступного лимита для возобновления. Теперь возобновление выделяет свободный нераспределенный остаток, сохраняя резерв и общий потолок. API-тест воспроизводит исчерпание → пополнение → возобновление → новый день.
2. Проверка даты только регулярным выражением пропускала 30 февраля. Добавлена проверка существования даты; тесты отклоняют 2026-02-30 и принимают 2028-02-29.
3. CSV защищал лишь формулу в самом первом символе. Добавлена защита перед пробелами/табуляцией/переводом строки; тест также проверяет кавычки и разделитель.
4. В Python-мосте исправлены пустой адрес Ollama по умолчанию и сборка UTF-8 по границам чанков; настоящий Node → Python тест возвращает русский текст.
5. Ответы чтения подключений теперь сбрасываются при переключении бизнеса, чтобы не показывать ответ от предыдущего бизнес-контекста. Live-UI этого сценария еще требует проверки с двумя подключениями.
6. При первоначальном прогоне новый тест исчерпания продолжал симуляцию уже остановленного бизнеса. Исправлен тест: останавливает цикл при паузе. Финальный прогон выше не имеет ошибок.
7. Ранее исправлены показ ошибки внутри открытого диалога, привязка Яндекс OAuth к выбранному бизнесу и распределение стартового демографика без искусственного последнего всплеска. Старые сохраненные демоданные не перезаписываются автоматически.
8. Время событий использовало зону браузера. Теперь используется зона бизнеса: браузерная проверка дала 23:29 для Asia/Yekaterinburg, 21:29 для Europe/Moscow и снова 23:29 после возврата. Аналогичное форматирование применяется к истории и времени анализа.
9. Сохранение профиля перераспределяло лимиты даже при изменении только часового пояса. Теперь перераспределение выполняется только при изменении общего бюджета; добавлен API-регрессионный тест.
10. `NODE_ENV=development` из локального `.env` увеличивал production-бандл за счет отладочной React-сборки до 566 kB. Настройка удалена из локального файла и примера; текущий финальный JS — 300,04 kB, gzip 91,69 kB, предупреждение исчезло. В Docker production задается отдельно.
11. Интерфейс сверки округлял деньги до рублей, из-за чего различие в копейках могло выглядеть нулевым. На экране отчётов суммы теперь всегда показаны с двумя знаками.
12. Worker мог принять сокращённый TSV и подставить нули для отсутствующих метрик. Перед сохранением теперь обязательны Date, CampaignId, CampaignName, Cost, Clicks и Impressions; повреждённый ответ не заменяет последний корректный снимок.
13. После успешного обмена OAuth-кода приложение теряло новый токен, если последующая проверка Direct завершалась таймаутом. Теперь токен сначала сохраняется зашифрованным, временная ошибка оставляет статус `pending` и допускает повторную проверку без нового OAuth; невосстановимая ошибка восстанавливает предыдущее подключение. Добавлены три регрессионных теста и API-тест обновления списка кабинетов.
14. Node.js не устанавливал соединение с IPv6-адресом API Метрики, хотя IPv4 был доступен. Клиент Метрики переведен на ограниченный HTTPS-транспорт с IPv4 и теми же таймаутами; реальный E2E после исправления вернул два счетчика и две цели выбранного счетчика.
15. Общий live-gate блокировал даже сохранение локальной анкеты бизнеса. Безопасная команда `settings` отделена от рекламных действий: сайт и профиль теперь сохраняются, а `launch` и остальные внешние/денежные команды по-прежнему возвращают 409. Добавлен API-регрессионный тест.
16. Истекший OAuth-токен требовал полного ручного переподключения. Добавлены зашифрованное хранение и атомарная ротация refresh token, обновление за пять минут до вычисленного истечения, один повтор чтения после auth-ошибки, single-flight для конкурирующих запросов и явный `reauth_required` при невосстановимом refresh. Обычная ротация не отменяет ожидающий read-only отчет; повторное подключение отменяет. Добавлены восемь provider/OAuth/API/Reports-тестов. Реальный токен рассчитан до 27 октября 2027 года, поэтому принудительная внешняя ротация не выполнялась.

Следующий этап — ненулевой production-отчет Direct при появлении данных и, только при отдельном письменном согласовании, ограниченная проверка черновиков в production-кабинете. Одобрение API и успешное чтение сами по себе не превращают эту версию в production.
