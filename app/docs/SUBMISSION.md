# Передача тестового задания «Ритм»

Это актуальная точка входа для проверяющего. Исторические планы и промежуточные числа тестов в других документах сохранены как инженерный журнал; текущие результаты приведены здесь и в [STATUS.md](STATUS.md).

## Запуск без внешних аккаунтов

Требуются Docker Desktop и файл `.env`, созданный из `.env.example`. Для демо достаточно сгенерировать постоянный `TOKEN_ENCRYPTION_KEY`; Client ID и secret можно оставить пустыми.

```sh
docker compose build
docker compose up -d
```

Откройте `http://localhost:4310` и выберите «Попробовать демо». Публичный домен и HTTPS для локальной приёмки не требуются. Реальные показы и списания закрыты конфигурацией.

## Что показать за 5 минут

1. Создать демо-бизнес и пройти краткий онбординг.
2. Открыть «Моя реклама»: показать план, бюджет, аудиторию, объявления и dry-run с нулём внешних write-вызовов.
3. Открыть «Сверка данных»: показать раздельные снимки Direct и Метрики и отсутствие выдуманной атрибуции кампании.
4. Открыть «Эксперименты»: показать фиксированную гипотезу, минимальную выборку и запрет раннего объявления победителя.
5. Открыть историю: показать идемпотентность, причины действий и безопасный компенсирующий сценарий.
6. Открыть подключения: показать Google OAuth и подключение собственного Яндекс-кабинета как конфигурируемые возможности; для демо ключи не нужны.

## Границы результата

- Реальный пилот создал только выключенные объекты Direct; показы и списания не запускались.
- A/B-контур, статистика по двум объявлениям и компенсирующие действия реализованы, но реального split-трафика нет.
- Генерация изображений через Cloudflare подготовлена и выключена без ключей; видео не входит в базовый объём.
- Перед публичной передачей требуется перевыпустить ранее раскрытый Yandex Client Secret.
- Настоящие данные рекламодателя, маркировка, модерация и денежные действия требуют отдельного решения владельца.

## Чистый комплект исходников

```sh
npm run submission:prepare
```

Команда создаёт новую версионированную папку `output/ritm-test-submission-<UTC-время>` только из исходников, тестов, документации и шаблонов конфигурации. В комплект не попадают `.env`, базы, OAuth-токены, browser profiles, `node_modules`, собранный `dist` и локальные отчёты. `SUBMISSION-MANIFEST.json` содержит размер и SHA-256 каждого файла.

До добавления `.env` получатель может проверить целостность чистой копии из её каталога:

```sh
npm run submission:verify
```

Из корня проекта команда автоматически проверяет последний созданный комплект
в `output`. Внутри передаваемой папки она проверяет её собственный манифест.
Конкретный путь также можно передать после `--`.
