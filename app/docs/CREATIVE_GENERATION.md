# Варианты генерации изображений и видео

## Рекомендация для проекта

Начать с изображений, а видео добавить вторым этапом. Публичный сервер использует `gpt-image-2.5-flare` по API-ключу владельца бизнеса. Ключ шифруется отдельно для каждого бизнеса. Локальный FastSDCPU/OpenVINO с `Stable Diffusion 1.5 INT8` остаётся вариантом для разработки без платы за запрос.

Для видео полностью бесплатного и одновременно надежного production API нет. Лучший бесплатный технический вариант — отдельный локальный GPU-worker с Wan 2.1 или Wan 2.2. Если подходящей видеокарты нет, для тестового задания разумнее сначала собирать ролики из изображений и пользовательских материалов через Canva либо Firefly вручную, а в сервисе оставить заменяемый интерфейс провайдера.

## Архитектура без привязки к поставщику

Провайдер генерации должен получать задачу из очереди и возвращать ассет с метаданными:

- `provider`, `model`, версия workflow и локальный идентификатор варианта;
- исходный prompt и negative prompt;
- тип `image` или `video`, размеры, длительность и MIME;
- hash файла, путь в object storage и превью;
- лицензия модели и дата проверки условий;
- статус policy check и результат ручного согласования;
- связь с бизнесом, кампанией, гипотезой и вариантом A/B-теста.

До первой публикации пользователь видит предпросмотр. Автоматическая публикация запрещена, если ассет содержит сомнительные утверждения, чужие бренды/лица, запрещенную категорию, некорректный текст, неизвестную лицензию либо не прошел модерацию площадки.

## Практический первый релиз

1. Добавить загрузку изображения пользователем.
2. Запустить FastSDCPU API со Stable Diffusion 1.5 INT8 через OpenVINO.
3. Генерировать выбранную рекламную концепцию: желаемый результат, живой момент или сильный ракурс. Новая генерация расходует одну единицу дневного лимита, поэтому три варианта запускаются осознанно, а не автоматически.
4. Сохранять prompt, модель, seed, визуальный крючок, условия провайдера и hash.
5. Требовать ручное подтверждение перед добавлением в Direct.
6. Из подтвержденного изображения собирать простой motion-ролик; полноценный Wan-worker подключить после проверки GPU и времени генерации.

## Реализованный рекламный workflow

Форма больше не отправляет провайдеру свободный prompt без контекста. Пользователь задаёт сцену, рекламную цель (`заявки`, `доверие`, `выгода`), визуальный крючок (`результат`, `живой момент`, `сильный ракурс`), аудиторию, визуальный подход и формат. Сервер добавляет категорию, услугу, город и преимущество бизнеса, затем фиксирует требования к одному правдоподобному рекламному кадру: без текста, логотипов, водяных знаков, ложных элементов интерфейса, коллажей и «до/после».

OpenAI GPT Image 2.5 Flare или локальный Stable Diffusion 1.5 INT8 создаёт исходник подходящей ориентации. После ответа изображение проходит отдельную подготовку через Sharp с attention-crop под формат размещения:

- `4:3` — 1200 × 900, основной рекомендуемый вариант;
- `1:1` — 1080 × 1080;
- `16:9` — 1200 × 675;
- `3:4` — 900 × 1200;
- итог всегда непрозрачный JPEG до 4 МБ;
- название компании берётся из сохранённого профиля и наносится сервером точным кириллическим текстом слева или справа внизу; модель сама буквы не рисует;
- в метаданных сохраняются формат, размеры, модель, лицензия и SHA-256;
- до ручного согласования публикация и передача в Директ запрещены.

Эти пропорции входят в допустимый набор изображений Яндекс Директа. Серверная подготовка гарантирует технический формат, но не гарантирует прохождение модерации: соответствие содержанию объявления, посадочной странице и правилам категории всё равно проверяет пользователь и площадка.

Prompt-конструктор сначала закрепляет конкретную рекламную цель, визуальный крючок и предметный контекст сферы, затем описывает сцену, естественный свет, правдоподобную анатомию и безопасную область композиции. Для сцен с руками добавлены предметные ограничения против лишних пальцев, отсоединённых кистей и парящих инструментов. Если выбрана плашка, модель получает только требование оставить спокойное место в нужном углу. Точное название добавляется после генерации через SVG-overlay в Sharp; длинные названия переносятся на две строки, спецсимволы экранируются, площадь плашки остаётся меньше 20% кадра.
