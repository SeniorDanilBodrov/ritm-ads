# Получение доступов для «Ритма»

Актуально на 24 октября 2026 года. На первом этапе используем только тестовый режим и чтение. Пароли, OAuth-токены и client secret нельзя отправлять в чат, скриншоты или Git.

## 1. Google OAuth для входа

1. Откройте [Google Cloud Console](https://console.cloud.google.com/) и создайте отдельный проект, например `Ritm Test`.
2. Перейдите в **Google Auth Platform**. В разделе Branding укажите название `Ритм`, email поддержки и контактный email.
3. В Audience выберите **External**, оставьте приложение в режиме Testing и добавьте Google-аккаунты, с которыми будет проверяться вход, в Test users.
4. В Data Access добавьте только `openid`, `email` и `profile`. Другие Google API этому проекту сейчас не нужны.
5. В Clients нажмите **Create client**, выберите **Web application** и укажите:
   - Authorized JavaScript origin: `http://localhost:4310`;
   - Authorized redirect URI: `http://localhost:4310/auth/google/callback`.
6. Сохраните Client ID. Client secret показывается только при создании — сразу сохраните его в защищённом месте.

Для будущего HTTPS-стенда создаётся отдельный production-клиент или добавляются точные адреса `https://<домен>` и `https://<домен>/auth/google/callback`. Схема, регистр, порт, путь и завершающий `/` должны совпадать с настройкой приложения.

## 2. Аккаунт разработчика Яндекс Директа

1. Войдите в Яндекс под стабильным аккаунтом разработчика, доступ к которому не будет потерян.
2. Откройте [Яндекс Директ](https://direct.yandex.ru/) и создайте аккаунт рекламодателя: укажите контактный email, страну и валюту.
3. Создайте одну черновую кампанию и одно черновое объявление с ключевой фразой. Отправлять их на модерацию и пополнять баланс не нужно. Это требуется, чтобы стала доступна страница настроек API.
4. В разделе Директа **Настройки API** примите пользовательское соглашение.

## 3. OAuth-приложение Яндекса

1. Откройте [Яндекс OAuth](https://oauth.yandex.ru/) и нажмите **Создать приложение**.
2. Выберите **Для доступа к API или отладки**. Тип после создания изменить нельзя.
3. Название: `Ритм — управление рекламой малого бизнеса`; укажите актуальную контактную почту.
4. Добавьте доступы:
   - `direct:api` — использование API Яндекс Директа;
   - `metrika:read` — чтение счётчиков, целей и статистики Метрики;
   - `passport:business` — только если используются логины организации.
5. Нажмите **Создать приложение** и сохраните ClientID и Client secret.

Для нового приложения этого типа redirect URI фиксирован Яндексом: `https://oauth.yandex.ru/verification_code`. Ввести `http://localhost:4310/auth/yandex/callback` нельзя. «Ритм» использует код подтверждения: открывает Яндекс в новой вкладке, а затем принимает код в разделе «Подключения». Код не нужно передавать в чат.

## 4. Заявка на API Директа

Текущий статус: заявка на полный доступ отправлена 24 октября 2026 года для приложения `Ritm Test`. PDF-спецификация со скриншотами приложена, пользовательское соглашение принято владельцем аккаунта. В разделе «Мои заявки» отображается статус `новая`; следующий шаг — дождаться результата рассмотрения.

1. Вернитесь в **Директ → Настройки API → Мои заявки**.
2. Нажмите **Новая заявка** и выберите созданный ClientID.
3. Укажите актуальный email и подробно опишите приложение. Подойдёт такой черновик:

> Веб-сервис «Ритм» помогает малому бизнесу самостоятельно вести рекламу в Яндекс Директе. Каждый владелец явно авторизует собственный кабинет. На первом этапе сервис только читает список кампаний и отчёты, сохраняет исходники, показывает расхождения и формирует рекомендации без автоматического исполнения. После отключения песочницы Яндексом тестирование операций изменения выполняется локальным dry-run и контрактными тестами; production-запись требует отдельного согласования. В дальнейшем операции изменения будут выполняться только после подтверждения пользователя, с идемпотентностью, журналом и контролем бюджета. OAuth-токены хранятся на сервере в зашифрованном виде и не передаются третьим сторонам.

4. Если форма спрашивает методы, укажите текущий read-only объём: Clients/Campaigns `get` и Reports; планируемые write-методы — только после отдельной приёмки.
5. Отправьте одну заявку для одного приложения. По официальной документации рассмотрение обычно занимает от часа до трёх рабочих дней, при нагрузке — до семи.

Песочница больше не является вариантом проверки: Яндекс официально отключил её 15 июля 2026 года. Одобрение заявки дает доступ к production API. В текущем этапе приложение использует его только для чтения; `LIVE_ADS_ENABLED=false` блокирует реальные рекламные операции.

## 5. Яндекс Метрика

1. Под аккаунтом, который будет проходить OAuth, создайте тестовый счётчик либо выдайте этому аккаунту гостевой доступ на просмотр существующего.
2. Откройте настройки счётчика и запишите его числовой ID.
3. Создайте тестовую цель или выберите существующую цель обращения; запишите ID и название.
4. Ничего из персональных данных посетителей передавать не нужно. Для первого E2E достаточно ID счётчика, ID цели и URL тестовой страницы со счётчиком.

`metrika:read` достаточно для чтения. `metrika:write`, `metrika:offline_data` и загрузку CRM-данных сейчас не запрашиваем.

## 6. Заполнение локального `.env`

В `app/.env` должны быть значения:

```dotenv
APP_ORIGIN=http://localhost:4310
TOKEN_ENCRYPTION_KEY=<32 случайных байта в base64>
GOOGLE_CLIENT_ID=<Google Client ID>
GOOGLE_CLIENT_SECRET=<Google Client secret>
YANDEX_CLIENT_ID=<Yandex ClientID>
YANDEX_CLIENT_SECRET=<Yandex Client secret>
YANDEX_SANDBOX=false
LIVE_ADS_ENABLED=false
```

Ключ шифрования можно создать локально:

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"
```

Файл `.env` уже исключён из Git. Не меняйте `LIVE_ADS_ENABLED`: наличие ключей разрешает только проверку подключения и чтения.

## Что можно сообщить в чат

- что Google-клиент создан;
- Google Client ID;
- что приложение Яндекса создано, и его ClientID;
- статус заявки Direct: черновик / на рассмотрении / одобрена;
- режим проверки: production read-only и локальный dry-run;
- логин прямого рекламодателя и валюта, если заказчик разрешает сообщить их;
- ID счётчика и цели Метрики, если это допустимо.

Не сообщайте client secret, `TOKEN_ENCRYPTION_KEY`, OAuth-токен, пароль, одноразовый код или cookies. После заполнения `.env` достаточно написать «готово» — значения будут проверены локально без вывода в журнал.
