# Приёмка Ритма

Последний зафиксированный P0-прогон: [P0_EVIDENCE_2026-11-05.md](P0_EVIDENCE_2026-11-05.md).

Проверка разделена на безопасный прогон и контролируемый live-пилот. Первый не
расходует деньги. Второй требует кабинета владельца, точного лимита и отдельного
подтверждения запуска.

## 1. Чистая установка

На машине без прежнего `node_modules` и локальной базы:

```sh
git clone <repository-url> ritm-ads
cd ritm-ads/app
copy .env.example .env
npm ci
npm run check
```

Для hosted-режима заполните `.env` и примените схему direct-строкой Neon:

```sh
npm run db:migrate:postgres
npm run db:verify:postgres
npm run production:preflight:strict
npm start
```

Откройте `/api/health` и `/api/ready`. Вторая проверка должна вернуть
`ready=true` и совпадающие версии схемы.

## 2. Безопасный пользовательский маршрут

1. Войдите через Google.
2. Расскажите Рите о бизнесе: название, услуга, город, преимущество и месячный
   бюджет.
3. Подключите Яндекс и выберите доступный кабинет.
4. Укажите страницу для клиента. Если сайта нет, используйте созданную Ритмом
   страницу.
5. Выберите, что считать обращением: форму, звонок или запись.
6. Проверьте план и согласуйте тексты.
7. В разделе изображений создайте вариант через Kie.ai и согласуйте его.
8. Нажмите тестовый прогон.

Ожидаемый результат: Ритм собирает команды, проверяет бюджетные ограничения,
моделирует отчёты, A/B-решение и откат. Внешних write-запросов к Директу и
списаний нет.

## 3. Создание выключенной кампании

Для этого этапа нужны:

```text
LIVE_ADS_ENABLED=true
DIRECT_WRITE_PILOT_ENABLED=true
```

Остальные write-флаги оставьте `false`.

В интерфейсе повторите проверку, подтвердите fingerprint плана и создайте
кампанию. Ритм должен:

- записать намерение до внешнего запроса;
- создать кампанию в выключенном состоянии;
- создать группу, не менее трёх согласованных объявлений и фразы;
- повторно прочитать все объекты;
- сохранить внешние ID и результат сверки.

В Директе кампания остаётся без показов. Повтор с тем же idempotency key не
создаёт копию. При неопределённом ответе операция переходит в
`needs_reconciliation`; повторная запись запрещена до read-only сверки.

## 4. Изображения

Включите `DIRECT_IMAGE_UPLOAD_PILOT_ENABLED=true` только на время проверки.
Загрузка разрешена для готового и вручную согласованного файла. Ритм проверяет
SHA-256 сохранённого содержимого, загружает файл в библиотеку Директа и читает
полученный hash обратно. Само это действие не запускает показы.

Созданные объявления должны ссылаться на сохранённый `AdImageHash`. Проверьте
его повторным чтением объявления через API, а не только по карточке интерфейса.

## 5. Модерация

Перед отправкой заполните в Директе настоящие данные рекламодателя, проверьте
страницу для клиента и маркировку. Затем временно включите:

```text
DIRECT_MODERATION_PILOT_ENABLED=true
```

Ритм отправляет на модерацию только сверенные объявления выбранной кампании.
Отправка не возобновляет показы. После ответа Яндекса выполните read-only
проверку решения.

## 6. Контролируемый запуск

Для закрытого пилота установите `LIVE_PILOT_BUSINESS_ID` в UUID одного бизнеса.
Для штатной приёмки с кабинетом проверяющего используйте
`LIVE_PILOT_BUSINESS_ID=*`: доступ определяется владельцем бизнеса, проверенным
подключением и подтверждениями в интерфейсе, без изменения конфигурации:

- ID кампании;
- периода;
- общего лимита и допустимого расхода;
- подтверждённого расхода на момент запуска;
- ответственного за остановку.

Только после этого включите `DIRECT_RESUME_PILOT_ENABLED=true`. Ритм повторно проверяет модерацию,
оплату, период, лимит с `AutoContinue=NO`, свежий отчёт и точные подтверждения
владельца. После единственного `Campaigns.resume` приложение читает состояние
обратно.

При неизвестном ответе не нажимайте запуск второй раз. Используйте сверку
resume-action. Остановку можно выполнить отдельным действием после того, как
предыдущая операция перестала выполняться.

## 7. Автопилот и бюджет

После успешного запуска и сохранения свежего корректного отчёта задайте
`AUTOPILOT_ENABLED=true` и настройте внешний
schedule-trigger по [RENDER_DEPLOY.md](RENDER_DEPLOY.md). На свежих отчётах
проверьте:

- shadow-review ничего не меняет;
- неэффективное направление получает подготовленное действие остановки;
- перераспределение сохраняет общий лимит портфеля;
- при применении сначала уменьшается донор, затем увеличивается выбранное
  направление;
- откат выполняет обратные действия в порядке, который не повышает возможный
  расход при частичном отказе.

Доказательство состоит из сохранённых отчётов, optimizer-action, истории,
read-back Директа и записи отката. Скриншота интерфейса недостаточно.

## 8. A/B

Вариант Б создаётся только при `DIRECT_AB_VARIANT_PILOT_ENABLED=true`. Он
остаётся выключенным до модерации и запуска. План теста фиксируется до трафика:
варианты, аудитория, период, минимальная выборка и правило решения.

После финального отчёта `DIRECT_AB_DECISION_PILOT_ENABLED=true` разрешает
применить вычисленное решение. До трафика разрешён только откат черновика Б;
после теста Ритм останавливает проигравшее объявление и проверяет состояние.

Если реальный трафик не согласован, принимается воспроизводимый тестовый прогон
с явной пометкой «симуляция». Его нельзя выдавать за production A/B.

## 9. Экспорт и мобильный интерфейс

Скачайте XLSX из раздела данных. Откройте файл в Excel или LibreOffice и
проверьте даты, рубли, строки источников и отсутствие формул из пользовательских
значений.

На ширинах 360, 390 и 430 px пройдите основной маршрут. Нижняя навигация не
должна закрывать кнопки и поля; карточки, график и дерево рекламы не должны
сжимать текст по буквам. Результаты visual-regression хранятся в
`output/playwright/` и не заменяют проверку на настоящем телефоне.

## 10. Протокол доказательств

Для live-пилота сохраните:

- время и commit SHA;
- обезличенные ID кабинета, кампании, группы и объявлений;
- fingerprint плана и idempotency keys;
- read-back после каждого внешнего действия;
- исходные отчёты Direct и Метрики;
- снимки до/после остановки, переноса остатка и отката;
- фактический расход и установленный предел.

Токены, API-ключи, ИНН, email и данные клиентов в протокол не входят.
